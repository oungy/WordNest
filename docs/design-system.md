# 统一视觉与交互规范

2026-11-04，设计修订 3。用户明确要求：任何会出现在眼前的小界面都要与整体风格统一；可以适量使用 iOS 风格的毛玻璃、半透明和圆角，但不能过度。

## 视觉层级

1. 内容层：词汇、例句、阅读正文保持稳定清晰的实色底；不在段落后堆叠模糊和高光。
2. 控件层：输入、选择器、按钮使用统一 17px 圆角与颜色标记；Android 实现映射为 dp，不把浏览器 px 当成设备像素。
3. 浮层：选择菜单和底部面板采用 25px 圆角、细边缘、低强度阴影；仅这一层与导航使用毛玻璃。
4. 导航：圆角浮动容器；选中状态以柔和底色、图标和文字表达，避免醒目蓝色高亮脱离主题。

预览材质：浅色玻璃以接近纸色的高不透明度为主，深色玻璃提高底色遮蔽；backdrop blur 22px、轻度饱和度调整。它是表达设计方向的 CSS，不宣称复现 Apple 的 Liquid Glass 或原生 Android 效果。

## 统一选择控件

- 本次上下文、主题、强调色、界面语言、AI 语言、发音、模型状态使用同一组件。
- 收起态为圆角按钮、当前值与统一箭头；展开态为靠近触发位置的圆角浮层。
- 选中行使用主题浅底、主题文字与勾选标记；没有默认蓝色矩形菜单。
- 上下文条目带简短说明，帮助区分自由聊天、当天词汇与自定义词本。
- 打开时定位当前项；上下键导航，Home/End 到首末，Enter/Space 选择，Escape 或点击外部取消。
- 关闭后返回触发器焦点；取消不修改选择。窄屏时换行并约束浮层位置，不能越出手机界面。
- 禁用的模型选择器仍采用相同外观，清晰显示等待条件，不生成空白下拉框。

## 其他控件也要一致

- 开关、复选框、滑块、输入、焦点边框、关闭按钮与删除确认使用相同的颜色和圆角体系。
- 所有选择状态除了颜色，还应有文字、勾选或明确开关位置。
- 自定义样式仍保留原生可聚焦按钮／输入及可访问性语义，不以不可操作的图形代替真实控件。
- 保留有意义的焦点提示；不要为了截图好看移除键盘焦点。
- 预览组件禁止弹出浏览器原生 alert/confirm/prompt；表单错误在同风格区域内显示。

## 舒适度和回退

- 设置提供“减少透明效果”；系统请求减少透明效果时也采用不透明表面。
- 不支持 backdrop-filter 时保持实色表面，不用完全透明的面板作为回退。
- 减少动画时关闭浮层缩放与移动；普通浮层动画约 160ms，不持续循环。
- 浮层仅使用轻微位移／缩放，不让整层文字随 opacity 淡入，避免过渡期间文字与背景重叠。
- 原生 Android 版本根据设备能力和功耗选择模糊实现或实色回退；避免在每个卡片上独立执行实时模糊。
- 保持足够文字对比度，检查浅／深主题以及改变强调色后的状态；Android 触控目标保持至少 48dp。

## 参考与边界

- [Apple HIG：Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：参考材质层级、内容可读性与减少透明效果的适配思路。
- [Android Compose：Menus](https://developer.android.com/develop/ui/compose/components/menu)：后续原生实现使用 Compose 可主题化组件和统一设计 token，而非依赖此 HTML。
